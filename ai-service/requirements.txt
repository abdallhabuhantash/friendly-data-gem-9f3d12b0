# Supabase client set. Pinned as ONE mutually compatible bundle, chosen as the
# smallest set that satisfies every constraint at once:
#   * supabase 2.16.0 is the FIRST release that accepts the opaque API-key
#     formats (sb_publishable_* / sb_secret_*); earlier releases reject them in
#     create_client() because the key had to be JWT-shaped.
#   * The sub-clients are pinned exactly because supabase >=2.16 passes
#     http_client= to postgrest/storage3/functions. A stale transitive
#     postgrest (e.g. 0.19.3 left over from supabase 2.11.0) raises
#     "SyncPostgrestClient.__init__() got an unexpected keyword argument
#     'http_client'" on the first table access. Explicit pins force pip to
#     upgrade those leftovers in an existing environment.
#   * Newer bundles (supabase 2.3x / storage3 2.3x) require pydantic>=2.11.7
#     and are therefore NOT installable beside this project's pydantic pin.
#     This bundle installs cleanly with pydantic==2.10.4, so FastAPI, pydantic
#     and pydantic-settings stay untouched.
# Do not loosen, upgrade or downgrade these lines individually.
